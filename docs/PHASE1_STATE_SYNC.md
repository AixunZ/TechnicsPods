# 第一阶段：核心控制与状态同步

日期：2026-10-09。测试候选：0.10.0-beta.1 / versionCode 30。

## 基线与范围

用户已确认原有模块在融合设备中心、蓝牙设备详情页正常显示，并可以显示和切换关闭、降噪、通透。记录中的测试基线为 Xiaomi nezha、Android 17、HyperOS OS4.0.0.17.XPACNXM，EAH-AZ100 固件 JNZ1ZE 1.040，Technics Audio Connect 4.4.0；本次未重新核验硬件版本。

本次处理第一阶段的 Settings 写入故障。没有实现第二阶段的统一连接所有权、官方 App 自动让出/恢复，也没有新增 EQ、通透强度、设备流转或通知产品界面。

故障证据：2026-10-09 提供的 LSPosed 日志记录了 `updateAncMode(int,boolean)` 的用户点击参数 `[0,true]`、`[2,true]`、`[1,true]`，随后每次都是 `module write bridge disabled`。控制中心使用的 MiLink `setAncState/setAncStateBlock` 路径仍能工作，故障限定在 Settings 的旧式 Fragment 回调。

## 检查后确定的方案

- 使用现有 Java 17、libxposed API 102、JUnit 4.13.2，无新增应用依赖。
- 移除系统 Hook 的永久模式覆盖，以共享仓库里的已确认读回状态为准。
- 保留原有 RFCOMM 读前状态、写入 ACK、强制回读流程，提取可测试的控制事务。
- 系统 Hook 后台执行蓝牙操作，不再等待 Future。同步返回上次确认模式或 -1（未知/忙），不提前返回目标模式。完成后发布状态并通知宿主重读。
- Provider 仅向既有允许包提供受限的确认结果/失败发布接口；校验模式、等级和请求与回读的一致性。没有开放原始命令或任意字段写入。
- 仓库在模块进程中使用共享锁完成读取、合并、保存，再发出 ContentResolver 状态变更通知。
- MiLink 桥接失效本地短缓存，并尝试调用已采集签名的 AncBatteryController.notifyPropertyChanged(BluetoothDevice,int,long)，更新类型 4/8 参考本地 HuaweiPods 实现。Settings 通过弱引用刷新已识别的存活 Fragment。
- 后台采样携带起始时间，较早的采样不能覆盖后来确认的控制结果或失败状态。仅电量/子模式读取不会延长旧三态模式的有效期。
- 单次控制有 15 秒总期限，取消关闭 socket；每次交换前和回读后检查取消。取消/超时后不发恢复写入，也不发布成功。
- Settings 的 `updateAncMode` 只接受 `0..2`；`updateAncLevel` 只接受 `1..100`，且均要求用户点击标志为 `true`。等级请求先读取当前模式，再保留原环境声值执行写入。

## 回归清单

1. 安装 v29，重启已有作用域。确认两个系统入口仍可显示并切换三态。
2. 每次点击允许先保留原状态；回读成功后，当前页面应更新为目标模式，模块监测面板同步。
3. 开启已有后台监测，用耳机触控改变模式；下次完整采样后，保持打开的页面应同步，不再被上次模块操作覆盖。此阶段仍是完成一轮读取后等待 30 秒的监测机制。
4. 使用现有官方 App 独占测试流程改变状态，然后让模块再次成功采样，确认状态替换；本阶段不要求官方 App 与模块同时控制。
5. 操作期间将耳机入盒或断开连接，确认系统页面不卡死、不误报目标模式；已发出的无线命令无法撤回，失败后实际状态须由后续读取确认。
6. 快速重复点击：同一 Hook 实例有未完成操作时拒绝新请求，完成后可再次操作；本阶段没有跨进程命令队列。
7. 检查 LSPosed 日志中的 `AZ100 control confirmed and published`；若出现 `Host state notification unavailable`，记录 ROM 版本及入口。此时 getter 可读取共享状态，但打开页面的即时重绘尚不能视为通过。

8. 在 Settings 入口检查 `AZ100 Settings control confirmed and published`。分别点击关闭、降噪、环境声，再改变降噪等级；确认耳机实际变化、页面状态回读和控制中心状态一致。重复快速点击一次，确认不会建立并发 RFCOMM 写入。

没有状态时不注入“关闭”作为默认值；若 Settings 控制失败，页面应等待后续状态读取，而不是把失败请求显示成成功。
